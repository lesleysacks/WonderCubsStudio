# M0.5 — Known Limitations

Items deliberately left open, with the reason and the suggested owner milestone. None blocks the M0.5 completion criteria. Items marked **decision** need your input.

| ID | Limitation | Impact | Why not fixed in M0.5 | Suggested |
|---|---|---|---|---|
| L-01 | **Unlinked workspaces.** Workspaces that migration 2 could not link with certainty (hand-made Sprint 3.4 workspaces, ambiguous duplicate titles), and workspaces created with the Workspace screen's **New** button, have no project link. Saving them never changes a project's status | Users of Sprint 3.4-era data may expect status sync for those workspaces | Linking needs a UI choice ("Link to project…" picker) and a rule for conflicts. That is an architectural/UX **decision**, and guessing would repeat D-01 | **Decision**, then M1 (Workspace folds into Project) |
| L-02 | **Legacy statuses on linked workspaces.** A linked workspace still holding `In Progress`/`Ready` (pre-lifecycle values) must be given a lifecycle status before it can be saved | One extra click for old data; the error names the invalid status | Mapping `In Progress` → `In Production` rewrites user values on a semantic guess | **Decision**: accept the prompt, or approve a documented one-time mapping |
| L-03 | **No real user database tested.** Fixtures are reconstructions built from each release's own schema code | Unknown real-world quirks (manual edits, partial old upgrades) | None available in the repository or environment | Before release, run `python app.py` on a copy of a real v0.3 database |
| L-04 | **Filesystem plus database is not one transaction.** A power loss between the folder rename and the database commit can leave a folder without a row | That folder's number is skipped; no data is lost | Impossible to make fully atomic across two systems without a journal | Accept; revisit with the asset store (M4) |
| L-05 | **Backups are never pruned.** One backup per upgrade and per restore | Disk use grows slowly (only on upgrades) | Deleting backups is deleting user data; a retention policy needs your **decision** | M1: keep the last N, with a setting |
| L-06 | **Restore is CLI-only** (`python app.py --list-backups`, `--restore-backup <file>`). On failure the startup error dialog shows the exact command | Non-technical users need the command spelled out | A restore screen is new UI | M2 (new shell) or a small M1 dialog |
| L-07 | **Real file-manager launch not observed on Windows/macOS.** Command selection (`startfile` / `open` / `xdg-open`) is unit-tested; `xdg-open` is not installed in the audit container | Low | No interactive desktop available | Manual smoke test on each OS before release |
| L-08 | **Windows Documents redirection** (OneDrive, a moved Documents folder) is not detected; the default uses `%USERPROFILE%\Documents` | New projects may land in the local, not the redirected, Documents folder; still user-visible and changeable in Settings | Needs the Windows Known Folders API (ctypes) | M8 (platform polish) |
| L-09 | **Lock file without hashes.** Direct dependencies are pinned exactly and transitive ones in `constraints.txt`, but there is no `--require-hashes` | Weaker supply-chain guarantee than a hashed lock | A cross-platform hashed lock needs pip-tools or uv, a new dev tool to **decide** on | M1 |
| L-10 | **Logs still grow without rotation** (audit S-03) | Small | Out of M0.5 scope | M1 |
| L-11 | **U-01 refresh race verified on Linux/Tk 9.0 only.** Windows CI uses Tk 8.6 and passes the UI tests, but whether the original bug appeared there was not checked against the old code | None after the fix | Old code was not run on Windows | — |
| L-12 | **Running from source writes `__pycache__` into the source tree.** That is Python bytecode, not user data; packaged builds precompile | None for users | Standard Python behaviour | M8 packaging |
| L-13 | **Non-ASCII titles still give poor folder names** (`Café` → `Caf`, audit C-07). Data-folder and project-folder *paths* with non-ASCII characters work and are tested | Cosmetic, international users | Changes existing folder-naming behaviour; not requested in M0.5 | M1 |
| L-14 | **Workspace and project titles can now diverge** after a workspace rename (the project title and folder are not renamed) | Matches stored data; dashboard shows the project title | Renaming folders touches user files | M1 (single entity) |
| L-15 | **Node 20 deprecation warning** from `actions/checkout@v4` and `actions/setup-python@v5` in CI | Future CI breakage | Upgrade together with SHA pinning (audit S-05) | M1 |
| L-16 | **CustomTkinter 6.0** passed only a shallow open-every-screen check; it is excluded by the pin | — | Upgrading is a separate, tested change | Revisit only if CustomTkinter is kept past M2 |
| L-17 | **Tk interpreter limit on Windows.** In one process, Windows CI failed to create the 10th Tk interpreter (`tcl_findLibrary`, then `Can't find a usable init.tcl … No error`). CI therefore runs each UI test in its own process (`tests/ui/run_isolated.py`). `python -m pytest` running all UI tests in one process works on Linux and macOS but may hit this limit on Windows | Developers on Windows should run `python tests/ui/run_isolated.py` for UI tests | Upstream Tcl behaviour; the application itself creates one interpreter | — |
